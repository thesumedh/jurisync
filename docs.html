Overview

JuriSync Documentation

A development-time cross-jurisdictional compliance orchestration layer and Model Context Protocol (MCP) server for AI-assisted software engineering.

As developers build AI-enabled features using autonomous coding agents (Claude Desktop, Cursor, Antigravity), systems are deployed across international borders without automated visibility into regulatory divergence. A system built in the US may function fine under voluntary guidelines like the NIST AI RMF 1.0, but upon international release trigger mandatory high-risk conformity assessments under EU AI Act Annex III, or violate India's DPDP Act Section 8(7) data erasure rules.

Discovering these non-conformities during post-launch legal reviews forces costly architectural rewrites, schema overhauls, or regulatory fines. JuriSync shifts regulatory evaluation left into the earliest design phase before code leaves your editor.

💡 Why Not Just Ask an LLM?

Generic generative LLMs are prone to legal hallucinations—inventing statutory clauses, quoting repealed directives, and conflating voluntary best practices with legally binding mandates. JuriSync replaces ungrounded text with a deterministic evaluation pipeline backed by verified government gazette citations.

Quickstart

Quickstart in 5 Minutes

JuriSync can be utilized in three primary modalities:

Modality 1: Interactive Web Console

Visit the live interactive console at https://jurisync-one.vercel.app/. Enter a natural language feature description (or select one of the 4 preset scenarios) and press Ctrl + Enter to generate an instant regulatory blueprint.

Modality 2: Zero-Install MCP Server (`npx`)

Connect JuriSync directly to Claude Desktop, Cursor, or any agentic IDE with zero cloning:

claude_desktop_config.json 
{
  "mcpServers": {
    "jurisync": {
      "command": "npx",
      "args": ["-y", "jurisync"]
    }
  }
}

Modality 3: Terminal Headless Stdio Call

Execute the compliance pipeline from any shell via stdio:

bash / zsh / PowerShell 
echo '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"analyze_compliance","arguments":{"feature_description":"AI system filtering resume CVs in EU and India"}}}' | npx -y jurisync
Governance & Philosophy

Core Engineering Principles

1. Deterministic Rule Matching

Every finding emitted by JuriSync corresponds to a deterministic rule object containing exact statutory citations (e.g. eu_ai_act_employment_high_risk, in_dpdp_retention_erasure_mandate). Rules are curated and mapped to statutory triggers (`employment`, `biometric`, `health`, `autonomous_action`, `personal_data`, `children`).

2. Binding vs. Voluntary Stratification

Regulatory confusion often stems from treating voluntary guidance as binding law, or vice-versa. JuriSync strictly classifies all output:

  • [BINDING LEGISLATION]: Enacted statutes carrying legal enforcement mechanisms, statutory damages, or regulatory fines (e.g., EU AI Act, GDPR, India DPDP Act 2023, NYC Local Law 144, Illinois BIPA).
  • [VOLUNTARY FRAMEWORK]: Industry risk management standards and federal guidance (e.g., NIST AI RMF 1.0, EEOC guidance).

3. Zero-Egress Privacy Architecture

JuriSync is engineered with zero remote telemetry. Web console analyses run client-side in the browser; MCP stdio queries run locally in Node.js. No developer prompts, proprietary feature descriptions, or candidate resumes are ever transmitted to third-party servers.

Packaging

npm Package & CLI Specification

JuriSync is distributed on the official npm registry as jurisync (v1.0.1).

📦 Package Highlights
  • Zero Dependencies: Built entirely with standard Node.js libraries. No runtime dependency vulnerabilities.
  • Ultra-Lightweight: 41.7 kB tarball on registry (160 kB unpacked). Installs and executes in under 2 seconds.
  • Dual-Mode: Functions both as an executable binary (npx jurisync) and an ES Module programmatic SDK.
Install Globally or Locally 
# Install locally in a project
npm install jurisync

Programmatic SDK

Node.js SDK Usage

Use JuriSync directly in your CI/CD linters, GitHub Actions, or backend compliance microservices:

index.js (ES Module) 
import { orchestrateCompliance } from 'jurisync';

const feature = 'Automated candidate screening tool using CV parsing and facial video interview analysis in the EU and India';

// Run central compliance orchestration pipeline
const report = orchestrateCompliance(feature);

console.log('Signals Detected:', report.signals.tags.map(t => t.label));
console.log('EU Rules Triggered:', report.guidance.EU.rules.length);
console.log('India Rules Triggered:', report.guidance.IN.rules.length);
console.log('Cross-Border Tensions:', report.tensions.map(t => t.title));

// Export Markdown action checklist for GitHub PR
console.log(report.checklist);
Internals

5-Stage Orchestration Pipeline

When a query is received, JuriSync executes five deterministic stages in sequence (< 5ms total execution latency):

The 5-Stage Execution Flow
  1. Signal Extraction (signalExtractor.js): Parses text for token patterns, domain triggers, and autonomous decision indicators.
  2. Statutory Rule Matching (ruleEngine.js): Filters the 15 curated statutory rules against active signals across EU, India, and US.
  3. Jurisdiction Synthesis (knowledgeBase.js): Computes risk tiers (High Risk vs. Standard) and contextualizes obligations.
  4. Tension Detection (tensionEngine.js): Evaluates potential frictions between conflicting statutory mandates across borders.
  5. Checklist Synthesis (orchestrator.js): Merges findings into grouped Markdown tasks ready for developer PRs and sprint tracking.

Tension Detection

Cross-Border Tension Engine

The Tension Engine surfaces architectural friction where complying with one country's statutory obligation creates compliance challenges under another's.

⚠️ Classical Conflict: Audit Retention vs Erasure Mandates

US NYC Local Law 144 & EEOC: Requires employers to retain candidate scoring distributions and evaluation logs to conduct annual independent bias audits.
India DPDP Act Section 8(7): Mandates complete erasure of applicant personal data as soon as the recruitment purpose is satisfied, subject to a statutory legal-compliance exception.
Architectural Resolution: Development teams should decouple direct applicant identity data from anonymized statistical scoring distributions to satisfy both auditability and erasure duties simultaneously.

API Reference

Model Context Protocol (MCP) Tool Reference

JuriSync exposes three standard JSON-RPC 2.0 tools over stdio:

1. analyze_compliance

Runs the complete orchestration pipeline on a natural language feature description.

analyze_compliance Input Schema 
{
  "name": "analyze_compliance",
  "arguments": {
    "feature_description": "An AI recruitment system that parses employee resumes and scores candidates for interview rejection in the EU and India.",
    "jurisdictions": ["EU", "IN", "US"] // Optional, defaults to all
  }
}

2. get_statutory_rule

Retrieves the full statutory citation, legal classification, and developer action for a specific rule ID.

get_statutory_rule Input Schema 
{
  "name": "get_statutory_rule",
  "arguments": {
    "rule_id": "eu_ai_act_employment_high_risk"
  }
}

3. list_supported_regulations

Lists all 15 tracked international statutory instruments and regulatory bodies.

Ethics & Trust

Responsible AI & Governance Framework

Compliance automation requires strict architectural ethics:

  • Decision Support vs. Replacement: JuriSync is designed for engineers and architects to flag risks during sprint planning. It empowers informed dialogue with legal counsel.
  • Human-in-the-Loop Safeguards: Where AI makes automated evaluations affecting individuals, JuriSync enforces oversight mechanisms per GDPR Art. 22 and EU AI Act Art. 14.
  • Data Minimization: The system processes only the natural language feature description provided. No system code, applicant PII, or internal credentials are required or ingested.
⚖️ Legal Safe Harbor Notice

JuriSync is an automated technical decision-support and regulatory intelligence tool intended to assist software developers, system architects, and AI engineers in identifying potential compliance considerations during early-stage software design. It does not provide formal legal advice, legal representation, or a guarantee of compliance. All findings and classifications are illustrative and must be validated by qualified legal counsel admitted to practice in the relevant jurisdictions prior to deployment.

Future Scope

Engineering Roadmap (6 Phases)

The ongoing development roadmap includes:

Phase 1: Static Codebase & AST Compliance Scanning

Building AST static analyzers using Tree-sitter to inspect source code repositories directly for biometric libraries (face-api.js), automated decision branches lacking human oversight, and database models lacking automatic TTL erasure routines.

Phase 2: SMT / Z3 Formal Verification of Conflicts

Mathematical modeling of statutory constraints to compute formal satisfiability proofs for multi-jurisdiction data architectures.

Phase 3: Expanded Global Regulatory Coverage

Incorporating Singapore PDPA & AI Verify, Japan APPI, South Korea PIPA, Brazil LGPD, California SB 1047, and Canada AIDA.

Phase 4: GitHub Action CI/CD Gatekeeper

A lightweight jurisync-action that inspects Pull Request descriptions and diffs, posting automated compliance feedback before merging.

Phase 5: EU AI Act Annex IV Conformity Dossier Generator

Compiles machine-readable compliance dossiers in JSON-LD signed cryptographically with Sigstore / Cosign.

Phase 6: Multi-Tenant Enterprise Policy DSL

A declarative YAML/JSON DSL enabling enterprise governance teams to define custom internal ethical boundaries alongside public statutes.
